# HX Lab

HX Lab is a desired-state homelab repo. Treat repository code as intent; runtime command output is only observed evidence from that command.

## Architecture

- Active stack: Proxmox VE host, Fedora CoreOS VMs, Docker Engine/Swarm, Traefik ingress, Cloudflare/Authentik access, AdGuard Home DNS, and TrueNAS-backed storage/backups.
- `infrastructure/ansible/` configures only the Proxmox host/datacenter. The active inventory is `pve1.home.hovirix.dev` as root.
- `infrastructure/opentofu/stacks/` contains direct stacks only: `adguardhome`, `proxmox`, and `access`. There are no current OpenTofu modules; do not add one unless a durable boundary is needed.
- Fedora CoreOS source is `infrastructure/opentofu/stacks/proxmox/fcos/fcos.bu`; `build/fcos.ign` is generated by Butane and should be regenerated, not hand-edited.
- `platform/` is Docker Swarm service desired state. Stack names come from `taskfiles/services.yml`, not directory names in all cases: `paperless-ngx` deploys as `paperless`.
- `.opencode/` is repo-local OpenCode configuration, agents, commands, skills, and its own npm lockfile; do not treat it as platform application code.

## Commands

- Full local validation is `task check`, which runs `task check:lint` then `task check:security`.
- CI runs `task check:lint` in `.github/workflows/checks.yml` and `task check:security` in `.github/workflows/security.yml`.
- Security checks generate SBOMs in `.artifacts/sbom` with Syft, then scan them with Trivy; these artifacts are generated output.

## Operations

- Prefer Taskfile entrypoints over raw tools when secrets, stack ordering, or host selection are involved.
- OpenTofu commands should go through `task infra:plan`, `task infra:apply`, or `task infra:destroy`; each initializes its stacks automatically and uses `operations/scripts/tofu.sh` to inject SOPS-backed backend credentials and state encryption variables.
- `task infra:plan` renders FCOS Ignition before planning; `task infra:apply` depends on that render. Stack order is `adguardhome`, `proxmox`, `access`; destroy is reversed.
- Proxmox Ansible preview/apply commands are `task pve:plan` and `task pve:apply`; `site.yml` imports host config, node-local Proxmox config, then datacenter config.
- Swarm and services tasks set `DOCKER_HOST` via `operations/scripts/swarm-host.sh`, which picks the first reachable active manager from `swarm-01` through `swarm-03`.
- `task deploy` first creates missing Docker secrets from `secrets/platform.sops.yaml` and `secrets/identity.sops.yaml`, then deploys ingress, data, identity, observability, Vaultwarden, and Paperless stacks.
- `task bootstrap` order is infrastructure apply, Proxmox Ansible apply, Swarm init, then services deploy.

## Commit Convention

- Format is Conventional Commits: `type(scope): description`.
- Types: `fix`, `refactor`, `chore`, `feat`.
- Scopes: `infrastructure`, `platform`, `operations`, `deps`, `tools`, `secrets`.
- Use lowercase in commit messages. Do not capitalize the description after the colon.
- Do not run `git commit` without being asked.

## Secrets And Safety

- Secret material lives in `secrets/*.sops.yaml`; do not decrypt or print it to inspect values. Repo-local OpenCode config denies direct `sops` bash commands.
- `.pre-commit-config.yaml` always runs `nix fmt` and `trivy --config security/trivy.yaml fs --scanners secret .`.
- Avoid introducing Kubernetes, Talos, or FluxCD changes; the README says that implementation moved to the separate `kubelab` repository.
- Do not add new documentation structures such as `docs/`, runbooks, ADRs, or documentation agents unless the user explicitly asks; this repo currently uses executable workflow files as the source of truth.
