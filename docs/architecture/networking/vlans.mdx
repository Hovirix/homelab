---
title: "VLAN Segmentation"
description: "Logical network segmentation model defining trust zones and isolation boundaries."
---

The network is segmented into dedicated [VLANs](https://www.geeksforgeeks.org/computer-networks/virtual-lan-vlan/) to enforce explicit trust boundaries and eliminate implicit east-west trust.

All inter-VLAN routing and policy enforcement is performed exclusively by the OpenWRT gateway.

<Info>
  The default posture between VLANs is deny-by-default.
</Info>

## VLAN 10 — Management

<Badge color="blue" size="lg" stroke="true">Subnet: 10.10.0.0/24 </Badge> <Badge color="purple" size="lg" stroke="true">Gateway: 10.10.0.1 (OpenWRT) </Badge>

VLAN 10 defines the administrative control plane of the environment. It isolates infrastructure management interfaces from application and client networks.

### Scope

- Proxmox VE management
- Proxmox Backup Server management
- Security Onion management
- Administrative endpoints

No application workloads or client devices reside in this segment.

### Access model

- Accessible via WireGuard VPN or authorized management host
- Not directly accessible from client VLAN
- Cross-VLAN traffic is routed exclusively through OpenWRT
- Default posture: deny unless explicitly permitted

<Warning>
  VLAN 10 represents the highest trust boundary within the internal network.
</Warning>

## VLAN 20 — Server / Application

<Badge color="blue" size="lg" stroke="true">Subnet: 10.20.0.0/24</Badge> <Badge color="purple" size="lg" stroke="true">Gateway: 10.20.0.1 (OpenWRT)</Badge>

VLAN 20 defines the application and service plane of the environment. It hosts all platform workloads and supporting infrastructure services.

### Scope

- Reverse Proxy and Cloudflare Tunnel endpoint
- Identity Provider (Authentik)
- PostgreSQL database
- Observability stack
- Application virtual machines

No client devices or administrative-only interfaces reside in this segment.

### Access model

- Client access permitted only through designated ingress endpoints (HTTP/S)
- No direct access to database or management interfaces
- Inter-VLAN routing enforced exclusively by OpenWRT
- Default posture: deny unless explicitly permitted

<Warning>
  VLAN 20 is considered a semi-trusted zone and is isolated from both client and management planes.
</Warning>

## VLAN 30 — Client / WiFi

<Badge color="blue" size="lg" stroke={true}>Subnet: 10.30.0.0/24</Badge> <Badge color="purple" size="lg" stroke={true}>Gateway: 10.30.0.1 (OpenWRT)</Badge>

VLAN 30 defines the client access plane of the environment. It contains end-user and non-administrative devices.

### Scope

- Wireless clients
- Non-infrastructure endpoints
- User devices

No infrastructure management interfaces or internal service control endpoints reside in this segment.

### Access model

- Permitted access to application ingress endpoints only (HTTP/S)
- No direct access to management VLAN
- No direct access to database or internal service backends
- All cross-VLAN traffic routed and enforced by OpenWRT
- Default posture: deny unless explicitly permitted

<Warning>
  VLAN 30 is considered the lowest trust boundary and is treated as untrusted relative to internal service networks.
</Warning>
